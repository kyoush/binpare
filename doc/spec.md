# binpare

Binpare — A fast, minimal GUI tool to compare binary files. Implemented in Rust using eframe/egui.

## 目的

バイナリファイルを視覚的に比較し、差分を直感的に把握できる軽量なデスクトップツールを提供する。

## 範囲 (Scope)

- 本ツールは主にバイト単位のバイナリ閲覧と（必要に応じた）2ファイル比較をサポートする。ユーザーは単一ファイルの hexdump ビューで閲覧するか、分割ペインで2ファイルを並べて比較するかを選択できる。
- 表示は読み取り専用とし、デフォルトではファイルの編集機能を持たない（将来オプションで編集を検討）。

## 用語定義

- ファイルA / ファイルB: 比較対象の左側・右側のファイル。比較モード時に使用される。単一ファイル表示時はファイルAのみが表示される。
- オフセット: ファイル先頭からのバイト位置（16進数表記で表示）。

## ユーザーストーリー

1. ユーザーはアプリを起動し、ドラッグ＆ドロップまたはメニューからファイルを選択して閲覧を開始できる。
2. ユーザーは単一ファイル表示（デフォルト）と分割ペイン（比較）表示を切り替えられる。分割ペインを選択した場合は2つ目のファイルを指定して比較を行う。
3. ユーザーはスクロール操作で両ペインを同期して確認できる（同期はオン/オフ切替可能）。
4. ユーザーは差分の最初の位置にジャンプしたり、任意のオフセットに移動できる。

## 画面構成（最小受け入れ構成）

- ヘッダ: アプリ名、メニュー（ファイル/表示/ヘルプ）、開いているファイル名・サイズ・簡易ハッシュ表示（オプション）。
-- メイン領域: 単一ファイルビューまたは分割ペイン（左=ファイルA、右=ファイルB）をサポート。各ペインは次を含む:
  - オフセット列（16進）
  - 16進ダンプ列（バイト毎）
  - 右端に ASCII 表示列（表示できる文字は . や ● などで非表示文字を扱う）
- 差分ハイライト: 両ペインの差分バイトは色付け表示。スクロールは同期（デフォルト）。
- ステータスバー: 選択中オフセット、選択バイト数、比較結果の統計（差分バイト数／全体比）

## ファイル選択フロー

1. 起動後、ユーザーはファイルを選択して閲覧を開始できる。単独で選択した場合は単一ファイルの hexdump 表示になる。
2. 分割ペイン（比較）を行うには、UI の『比較を開始 / 分割ペインに切替』ボタンを押して2つ目のファイルを選択する。2つ目を指定すると自動で比較が行われる。
3. ドラッグ＆ドロップで 2つまとめてドロップした場合は、分割ペイン表示としてそれぞれ左/右に割り当てる（挙動は UX で調整可能）。

※ UX向上案: ドラッグ時に『ここにドロップでファイルA/Bを選択』といったホバーUIを表示する。

## バイナリ表示要件

- 表示は常にバイト単位で16進（例: hexdump -C 風）で行う。
- 1行あたりのバイト数は設定で変更可能（デフォルト 16）。
- ASCII 表示は右側に配置し、印刷可能文字はそのまま表示、非表示文字は '.' または '·' で表す。

## 差分表示ルール

- バイト単位の比較を行い、値が異なるバイトは両ペインで強調表示（例: 赤）する。単一ファイル表示時は差分ハイライトは無効。
- 差分が連続する場合は連続領域としてまとめてハイライト可能（オプション）。
- ファイル長が異なる場合、短い側の不足分は空白として表示し、長い側は差分として扱う。
- 行単位（同一オフセット範囲）で差分の有無を示す薄いマーカーを行ヘッダに表示する（差分ジャンプに利用）。

## 操作性（ショートカット/機能）

- Ctrl+O: ファイルを開く
- Ctrl+F: オフセット検索（16進/10進で入力可能）
- F3 / Shift+F3: 次/前の差分へジャンプ
- Ctrl+S: 差分レポートをエクスポート（任意）
- スクロール同期のON/OFF切替

## 大ファイルとパフォーマンス

- 目標: 数百MB〜数GB のファイルを扱えることを目指す（ただし最初の実装では 200MB 程度を目安）。
- 実装方針案: OS のメモリマップ（mmap）または遅延読み込み（仮想化）を用いて、表示領域のみにアクセスする。
- 長時間の読み込みはプログレス表示し、UI スレッドをブロックしない（読み込みは別スレッドで行う）。

## エラー処理／例外ケース

- ファイルが開けない（権限・ロック・存在しない）場合はユーザーに明確なエラーダイアログを表示する。
- 読み込み中にファイルが外部で変更された場合は再読み込みを促すか、警告を出す。
- サポート外のファイル（極端に大きい、デバイスファイル等）は警告し、安全に中断できるようにする。

## 非機能要件

- クロスプラットフォーム: Linux / macOS / Windows をサポート（依存は eframe/egui に準拠）。
- レスポンシブなUI（スクロールやジャンプ操作は 100ms 未満の応答を目標）。
- メモリ使用量に関しては表示領域のみをキャッシュすることで最小化する。

## 受け入れ基準（Acceptance Criteria）

1. 2つのファイル（各 1MB）を比較したとき、差分バイトが色付きで表示され、スクロールが同期することを手動で確認できる。
2. オフセット検索で指定した位置にジャンプでき、両ペインが同期してそのオフセットを表示する。
3. ファイルが 200MB 程度のサイズでも UI がフリーズせず、読み込みにプログレス表示が出る。

## テストケース（例）

- TC1: 小さなファイル（16バイト差）を比較し、差分箇所が期待通りハイライトされる。
- TC2: 長さが異なるファイルを比較し、長い側の余剰バイトが差分として表示される。
- TC3: 大きいファイル（200MB）を読み込み、プログレス表示と操作応答性が維持される。

## 実装ノート / 技術選択

- GUI: eframe/egui を使用する。クロスプラットフォーム対応を前提。
- ファイルアクセス: 初期は std::fs::File + read を用い高速化は段階的に実施（mmap は後段で導入）。
- 日本語表記: egui のフォント設定で日本語フォントを明示的に読み込む。

## 未解決事項 / 要確認

1. 初期リリースでサポートする最大ファイルサイズの明確な目標値（200MBで良いか）。
2. 差分のエクスポート形式（テキスト・JSON・パッチ）の仕様。
3. 編集機能を今後追加するかどうか（セキュリティ・保守性に影響）。

# binpare

Binpare — a fast, minimal GUI tool to compare binary files, built with Rust and eframe/egui.

## 仕様

### 起動画面

- 起動時はファイルの選択を待ち受ける
- ファイルを選択する方法は、以下の二種類である
  1. ユーザーが任意のファイルをドラッグアンドドロップする
  2. メニュー > ファイル > 開くボタンからファイル選択ポップアップを開き、そこから選択する

### バイナリビュー

- 拡張子にかかわらず、常に16進数でバイナリを表示する hexdump -Cの出力と同じようにする
- 右側にはASCIIエンコードを表示する
